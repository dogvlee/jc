# 功能规格：扫码建标 / 扫码填充

功能编号：SCAN-TO-LABEL
适用版本：`1.0.0-rc.1`
状态：代码路径已实现；冻结提交自动化归档与微信真机验收待执行

## 1. 用户问题

零售、仓储和资产用户经常已经拥有商品条码、货位码或二维码。此前他们必须先扫描到别的应用、复制内容，再在编辑器手工选择元素和粘贴，步骤长且容易输错制式或字符。

目标场景：

> 当用户面对一个现有条码或二维码时，可以从首页一次扫码生成可编辑标签；在已有设计中，也可以把扫描结果直接填入选中的编码元素，取消或失败不会破坏原稿。

## 2. 范围

### 本期包含

- 首页“快捷创建”中的“扫码建标”。
- 调用微信原生扫码，允许一维码和二维码。
- 一维码生成居中的 `barcode` 元素；二维码生成居中的 `qrcode` 元素。
- EAN-13 与 Code 128 格式推断。
- 使用当前默认耗材宽高创建文档。
- 编辑器选中条码或二维码后“扫描填入”。
- 用户取消静默返回；不可用、权限拒绝、空内容、超长内容或类型不匹配时给出可行动错误。
- 修改通过统一 `commit` 进入自动保存和撤销链路。

### 本期不包含

- OCR、图片文字识别、语音识别。
- Data Matrix、PDF417 的原制式重建。
- 扫描耗材包装自动匹配型号或尺寸。
- 连续扫描清单、扫描即自动打印。
- 上传扫描原文、图像或远程查询商品数据库。

## 3. 用户流程

### 3.1 首页扫码建标

1. 用户点击“扫码建标”。
2. 微信展示原生扫码界面；权限在此主动动作发生时申请。
3. 用户扫描一维码或二维码。
4. 系统验证非空、长度和类型。
5. 系统以默认耗材尺寸创建仅含一个编码元素的文档，并进入编辑器。
6. 用户可以继续移动、缩放、改值、保存和打印；不会直接自动打印。

### 3.2 编辑器扫描填入

1. 用户选中条码或二维码。
2. 点击“扫描填入”。
3. 条码元素只请求一维码；二维码元素只请求二维码。
4. 成功后更新选中元素，记录撤销快照并自动保存。
5. 取消时元素和撤销栈不变；失败时保留元素并展示恢复建议。

## 4. 规则

| 规则 | 行为 |
|---|---|
| 一维码识别 | `EAN_13`、Code 128、Code 39、UPC、ITF 等原生一维类型映射到 `barcode` |
| 二维码识别 | 非一维类型在首页入口映射到 `qrcode`；扫码请求当前只开放 `qrCode` 与 `barCode` |
| EAN-13 | 原生类型为 EAN-13，或结果为 12/13 位数字时推断为 `ean13`；打印前继续执行校验位检查 |
| Code 128 | 其他一维结果使用 `code128`；限定 ASCII 32–126 |
| 长度 | 总扫描内容最多 500 字符；一维码最多 80 字符 |
| 默认尺寸 | 使用 `stockWidthMm`、`stockHeightMm`，并钳制到 5–150 mm；缺失时使用 50×30 mm |
| 位置 | 新元素在文档中心；二维码保持正方形，一维码使用可读的横向区域 |
| 原稿安全 | 类型不匹配、失败或取消均不得修改当前元素 |
| 打印安全 | 扫码成功不绕过 `validateDocument`、printability 和连接握手，不触发自动打印 |

## 5. 功能需求

| ID | 需求 | 自动化/验收 |
|---|---|---|
| FR-SCN-001 | 首页必须提供“扫码建标”入口，且只在用户点击时调用扫码。 | WXML handler + 真机权限 |
| FR-SCN-002 | 扫描成功必须根据类型创建条码或二维码文档，并使用当前默认耗材尺寸。 | `scan-label.test.js` |
| FR-SCN-003 | 一维码必须推断 EAN-13/Code 128，并继续接受打印前编码校验。 | 单元测试 + 实物扫码 |
| FR-SCN-004 | 编辑器选中条码/二维码时必须提供“扫描填入”，成功后支持撤销和自动保存。 | 页面方法 + 真机交互 |
| FR-SCN-005 | 条码入口不得接受二维码并静默转换；类型不匹配时保留原值。 | 单元测试 |
| FR-SCN-006 | 用户取消扫码不得显示错误、创建草稿或修改元素。 | scanner mock + 真机 |
| FR-SCN-007 | 权限/平台失败必须说明检查相机权限；运行时不支持时说明升级微信。 | scanner mock + 真机 |
| FR-SCN-008 | 空、超过 500 字符、非 ASCII 一维码或超过 80 字符的一维码必须拒绝。 | 单元测试 |
| FR-SCN-009 | 扫码结果只能在本地文档中使用，不得自动上传、查询或打印。 | 代码审查 + 隐私验收 |

## 6. 状态与文案

| 状态 | 文案/行为 |
|---|---|
| 等待扫码 | 由微信原生界面显示，不在小程序叠加假进度 |
| 用户取消 | 直接回到原页面，不弹失败提示 |
| 权限或扫码失败 | “扫码失败，请检查相机权限后重试” |
| 环境不支持 | “当前微信环境不支持扫码，请升级微信后重试” |
| 内容为空 | “没有识别到可用内容，请重新扫描” |
| 类型不符 | “当前选中的是一维码，请扫描商品条码；二维码内容请放入二维码元素” |
| 成功填入 | “条码已填入”或“二维码已填入” |

## 7. 隐私与安全

- 权限按需触发，不在启动时请求相机。
- 当前实现不保存原始照片或 `rawData`，只使用微信返回的 `result` 与 `scanType`。
- 不记录、不上传、不写入诊断日志中的扫描原文。
- 扫描内容属于不可信输入，必须经过长度、字符集、文档和打印校验。
- 若未来接入商品查询、OCR 或遥测，必须重新评估隐私保护指引、网络域名、数据保留和用户同意。
