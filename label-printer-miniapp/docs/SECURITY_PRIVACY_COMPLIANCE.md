# 精臣标签小程序安全、隐私与合规交付说明

文档状态：发布前治理基线；未完成正式安全审计
适用版本：`1.0.0-rc.1`
更新日期：2026-08-11

## 1. 定位与免责声明

本文基于当前仓库代码、测试和发布清单，说明数据流、威胁面、已有控制、待补措施和发布合规门禁。它不是渗透测试报告、密码学证明、法律意见或微信审核通过证明。

当前不得宣称“已通过安全/隐私合规审核”，原因包括：正式 AppID、平台隐私保护指引、权限/类目配置、秘密扫描、真机 BLE、品牌及素材授权均无完成证据。

## 2. 当前安全边界

### 2.1 架构事实

- 当前业务代码未调用 `wx.request`、上传、下载或 WebSocket API，标签工作流按设计离线、本地优先。
- 项目、模板、设置、数据行、打印历史、设备绑定和草稿使用微信本地存储；用户图片复制到 `wx.env.USER_DATA_PATH`。
- CSV、模板 JSON、备份 JSON 和图片由用户主动选择；导出文件由用户主动分享。
- 标签在本地 Canvas 栅格化后通过 BLE 发送给附近打印机。
- 当前没有登录、云同步、支付、广告、统计 SDK、远程日志、远程配置或后端 API。
- 包内仍包含上游素材 API/OSS URL、在线模板来源元数据和 `vip` 标记。虽未发现运行时请求使用这些 URL，它们仍属于需最小化和确认授权的发布内容。

### 2.2 信任边界

```text
用户输入/本地文件（不可信）
        │
        ▼
WXML/Page 事件与解析器
        │
        ├── Repository / USER_DATA_PATH（本机持久数据）
        ├── 用户主动分享的 CSV/JSON（离开小程序沙箱）
        └── Renderer → BLE/GATT → 实体打印机（产生物理输出）

构建输入（依赖、源素材、上传凭据）
        │
        ▼
构建工作站/CI → 微信开发者工具/平台 → 分发包
```

用户文件、附近 BLE 设备、第三方依赖/素材、发布工作站和微信平台均在不同信任边界。不能因为应用没有后端就认为没有安全或隐私风险。

## 3. 数据清单与生命周期

| 数据类别 | 来源与用途 | 当前存储/上限 | 对外流动 | 当前删除/保留 |
| --- | --- | --- | --- | --- |
| 标签正文与元素 | 用户编辑；生成预览和打印 | 项目最多 120、模板最多 80；草稿/自动保存 | 栅格经 BLE 到打印机；可进入备份 | 可删项目/模板；无“一键清除全部” |
| 批量数据 | 表格编辑或 CSV 导入 | 最多 1000 行 | 可导出 CSV、进入打印内容 | 覆盖/编辑；无独立保留期 UI |
| 打印历史 | 打印结果、机型、设备名、错误 | 最多 80 条；前 10 条保留文档副本 | 可进入 JSON 备份 | 滚动淘汰；无逐条清理说明 |
| 用户图片 | 相册/相机，标签图片元素 | `USER_DATA_PATH`；代码无大小/数量上限 | 本地栅格后经 BLE 打印 | 替换/删元素不会清理孤儿文件，待补 |
| 扫码内容 | 用户主动调用 `wx.scanCode` 取得条码/二维码文本与类型 | 仅进入当前本地文档；不保存原图或 rawData | 可随文档备份或经 BLE 打印 | 取消/失败不写入；随元素/项目删除 |
| 设备绑定 | 蓝牙 device ID、名称、GATT/MTU/机型信息 | `niim-label:last-device`，直到忘记设备 | BLE/诊断使用；不应进日志 | “忘记打印机”可清除绑定 |
| 设置 | profile、浓度、阈值、纸型、引导状态 | 本地，直到重置/覆盖恢复 | 备份可携带 | 无完整设置重置入口 |
| 导入文件 | CSV/模板/备份 | 微信临时文件，解析后写入业务数据 | 用户选择的来源已在沙箱外 | 临时文件生命周期由微信管理 |
| 导出文件 | CSV、JSON 备份 | `USER_DATA_PATH` 明文文件 | 用户主动分享后离开沙箱 | 当前没有导出文件清理入口 |
| 运营证据 | 版本、错误、机型/固件、样张 | 当前人工管理 | 支持/QA 团队 | 必须脱敏并定义保留期 |
| 发布凭据 | AppSecret、上传私钥、平台会话 | 当前仓库不应包含 | 微信平台/受控 CI | 由密钥库和平台策略管理 |

应用没有对本地数据或导出文件实施应用层加密；保护依赖微信沙箱、手机系统和用户对导出文件的管理。隐私告知必须明确这一点，不能把“本地存储”表述为“绝对安全”。

## 5. 已实现的数据安全控制

- `normalizeDocument` 只接受 10 种支持元素，拒绝无效宽高，限制元素数、字符串、字号、间距、序列位数和表格行列/单元格；极端数值不会进入文本适配循环。
- 项目、模板、数据和历史设置数量上限，系统模板不整包写入用户存储。
- 旧 schema 迁移幂等；备份版本过新会拒绝恢复。
- 恢复写入失败会回滚已修改键，回滚本身失败有独立错误码并要求停止编辑。
- 打印前验证机型、尺寸、占位内容、条码/二维码和元素几何，不通过时不发送打印数据。
- BLE 会验证 E781 服务/主特征和协议握手；通用可写设备在发送协议字节前被拒绝。
- 断线会使协议 ready 状态失效；可能部分打印的任务不自动整批重放。
- 静态检查验证 JS/JSON/WXML、页面组合、事件处理器、资源引用和本地主包大小。
- 依赖版本由 lock 文件固定，`qrcode-generator` 和协议参考库已有 MIT notice。

这些控制有 Node 测试证据，但微信沙箱、文件系统、BLE 栈和实体打印效果仍是待验边界。

## 6. 最小权限与隐私告知

### 6.1 实际使用的平台能力

| 能力 | 使用时机与目的 | 最小化要求 | 拒绝后的安全行为 |
| --- | --- | --- | --- |
| 蓝牙适配器、扫描、连接、notify、MTU | 用户连接本地标签打印机 | 进入设备/打印流程时才使用；停止无效扫描 | 保留标签，提示开启蓝牙/权限，不显示假连接 |
| 相册/相机 `chooseMedia` | 用户主动添加标签图片 | 单次 1 张，仅图片；生产前增加大小/格式限制 | 不创建图片元素，编辑器继续可用 |
| 相机/相册 `scanCode` | 用户主动扫码建标或向编码元素填入 | 只请求一维码/二维码；不保存原图、rawData，不上传扫描原文 | 取消不打扰；拒绝/失败保留原文档并提供恢复文案 |
| 消息文件 `chooseMessageFile` | 用户主动导入 CSV/JSON | 限扩展名、大小、行数、schema 和复杂度 | 原数据不变，显示可行动错误 |
| 本地文件读写 | 保存用户图片、生成导出文件 | 只用 `USER_DATA_PATH`；文件名固定/时间戳；增加清理 | 保存/导出失败不虚报成功 |
| 文件分享 | 用户主动导出 CSV/备份 | 分享前说明可能含敏感标签数据 | 取消即停止，不后台上传 |
| 本地存储 | 草稿、项目、设置、历史、设备绑定 | 数量上限、失败提示、可备份/删除 | 写失败保留当前页面内容 |

当前不需要账号、联系人、麦克风、支付、精确位置内容或网络上传权限。Android BLE 扫描可能要求系统定位服务开启，这不等于应用有理由采集位置内容；文案必须区分“系统扫描前提”和“应用收集位置”。

### 6.2 发布前隐私文本必须覆盖

- 处理的数据类别、目的、触发时机、本地存储位置和保留方式。
- 蓝牙设备标识、用户图片、CSV/JSON、标签正文、打印历史的具体用途。
- 数据通过 BLE 发给用户选择的打印机，以及导出/分享后由用户自行管理。
- 当前没有后台上传、账号或云同步；如果未来增加统计/云功能，必须先更新告知与同意。
- 如何删除项目/模板、忘记设备、导出备份，以及当前缺少完整清理入口的处理计划。
- 权限拒绝后的恢复方式、客服/隐私联系人和投诉渠道。

首页一句“默认不上传网络”不能替代完整隐私政策和微信小程序隐私保护指引。

## 7. 不可信导入与导出治理

### 7.1 导入

生产前应为 CSV、备份 JSON、模板 JSON 和图片建立统一入口策略：

1. 读取前检查字节大小；模板已有 2 MiB 限制，CSV/备份待补。
2. 限制 CSV 最大行数、每字段长度和总字符；先验证再一次性提交。
3. JSON 限制嵌套深度、数组长度、字符串长度和允许字段；设置使用字段白名单而非任意合并。
4. 图片限制 MIME/扩展名、像素、字节和解码结果，必要时压缩后再持久化。
5. 任何解析/写入失败保持原数据，不能部分显示“导入成功”。
6. 模糊测试损坏编码、超长字段、重复 ID、未知元素、极端宽高和恶意文件名。

### 7.2 导出

- CSV 在面向 Excel 等软件时，对公式前缀采取转义/告警策略，并说明兼容影响。
- JSON 备份导出前明确它可能含标签正文、条码、历史和项目，不应发到公共群聊。
- 提供导出文件清理或明确平台文件生命周期；不长期累积多个明文备份。
- 支持场景使用合成/脱敏备份，不要求用户发送原始生产数据。

## 8. BLE 与物理输出安全

- 只连接用户明确选择的设备；显示设备名、机型 ID/协议和连接结果。
- 服务/特征匹配只能排除普通设备，不能提供密码学身份保证。硬件负责人需确认目标固件是否支持配对、绑定或应用层认证，以及不支持时的可接受风险。
- 未知机型、300 dpi 未验证型号或相似名称不得套用 profile。
- 诊断只做适配器/GATT/协议握手，不发送打印行；诊断证据仍需隐藏设备 ID。
- 打印前必须显示设备、标签尺寸、纸型、份数和阻断原因。
- 取消、断线、超时后提醒用户先看纸面；只有用户明确确认才能重印剩余内容。
- 不接入 FF00/FF02/FF03 ESC/POS credit 流控，避免把不同协议的控制机制当成安全/稳定性修复。

## 9. 日志、遥测与事故数据

当前无远程日志是隐私面较小的优点，也是运营检测缺口。未来增加遥测前必须完成数据保护评审。

允许字段白名单：版本、环境、手机/系统/微信版本、打印机机型族/固件、阶段、错误码、耗时、MTU、连接来源、成功/失败/取消。设备 ID 仅可使用项目独立盐散列或末四位。

禁止字段：标签正文、价格、姓名、条码/二维码、CSV 行、图片、备份内容、完整设备 ID/蓝牙地址、打印机序列号、AppSecret、上传私钥、平台 token。

还需定义：采集合法依据与同意、采样率、保存期限、访问角色、导出/删除请求、事件字典版本和供应商。未完成这些项前只允许脱敏人工 QA 记录。

## 10. 发布凭据与供应链

### 凭据

- 上传私钥只能进入受控密钥库；保持现有忽略规则，并建立 pre-commit/CI 秘密扫描。
- 密钥只保存在组织密钥库或受控工作站，限制读取和发布权限，记录使用审计。
- 怀疑泄露立即吊销/轮换，检查 Git 历史和已发布包，按 SEV-0 处理。
- AppSecret 永远不应进入小程序客户端；需要服务端能力时由受控后端持有。

### 依赖与构建

- 候选版只用 `npm ci` 和已评审 lock；依赖升级单独提交并重新生成 vendor。
- 记录 Node、npm、esbuild、Pillow 和开发者工具版本；当前 Node/Pillow 固定机制仍待补。
- 对 npm/Python 依赖执行许可证、漏洞和来源审查；生成物与输入建立哈希清单。
- `scripts/optimize_assets.py` 从同级源应用读取资源，不应在无授权/无固定输入时运行。

## 11. 品牌、素材与第三方合规

现有 notice 覆盖 `niimbluelib` 参考实现和 `qrcode-generator`。它不自动覆盖：

- “精臣/NIIMBOT”商标、名称、图标和产品外观。
- 189 个模板及其缩略图、在线图片、素材和带 `vip` 标记的内容。
- 从上游 JSON 保留的 OSS/API URL、用户资源路径和元数据。
- 模板中引用的字体名称及可能对应的字体资产/使用权。

发布前建立逐项资源台账：文件/模板 ID、来源、作者/权利方、许可证或授权文件、允许用途/地域/期限、是否可修改/再分发、署名要求、审核人。没有证据的资源必须移除或替换为自有内容。

逆向分析、协议兼容和网络可访问不等于获得商业再分发授权。未经法务/内容负责人签字，不得发体验版给外部用户或提交生产审核。
