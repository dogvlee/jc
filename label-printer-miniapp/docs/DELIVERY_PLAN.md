# 精臣标签小程序闭环交付计划

文档状态：工程候选基线；主线冻结验证与外部发布门禁待执行

更新日期：2026-08-11

## 1. 交付原则

本计划以可验证的功能对齐为目标。每一阶段必须同时产出代码、测试证据和可回滚结果；“代码已写”不等于“可上线”。原 Web 应用是行为参考，小程序代码、平台适配和 BLE 链路均在目标项目内独立维护。

发布完成的定义是：自动化门禁全绿、微信开发者工具和真机矩阵全绿、正式 AppID 与合规材料就绪、灰度验证无 P0/P1 回归。缺一项只能称为“工程交付”或“候选版本”，不能称为上线完成。

## 3. 目标架构

```
页面层
├─ pages/home     首页、模板、项目、数据、我的虚拟路由
└─ pages/editor   画布编辑、属性、图层、预检与打印
        │
应用服务层
├─ Repository                本地 schema、迁移、项目/模板/历史/备份
├─ PrinterConnectionManager  连接复用、重连、诊断、设备记忆
├─ PrinterClient             NIIMBOT 握手与打印任务执行
├─ Scanner                   Promise 化微信原生扫码与取消/权限错误
└─ CSV / Data Binding        导入导出与模板字段绑定
        │
领域核心层
├─ Document / Geometry / Gesture / Renderer
├─ Scan Label                扫码类型、长度、建标与安全填入规则
├─ Template Catalog / Layout / Materials
├─ Profiles / Print Plan / Image Encoder
└─ Protocol / BLE Session
        │
微信平台层
├─ Storage / File / Image / Canvas / Scan Code
└─ Bluetooth Adapter / GATT / Notify / MTU
```

关键边界：页面不自行长期持有或关闭全局 BLE 连接；打印机协议不依赖页面生命周期；系统模板不写入本地仓储；编辑文档与打印机能力分离，只有预检负责判定能否打印。

## 5. 迁移映射

| 原应用能力 | 小程序落点 | 迁移策略 |
| --- | --- | --- |
| SPA 路由与视图 | `pages/home` 虚拟路由 + `pages/editor` | 复刻旅程，改用小程序 Page 生命周期和数据绑定 |
| 浏览器状态/store | `Repository` + Page data | 明确 schema 和容量上限，避免持久化系统模板全集 |
| Canvas 编辑器 | 小程序 2D Canvas | 保留毫米坐标领域模型，视图层按设备像素比缩放 |
| 模板与在线资源 | 本地 catalog、压缩 PNG | 固化 189 模板，资源离线化；发布前完成授权审核 |
| CSV/文件 API | 微信选择文件/本地临时文件 | 对编码、行数、字段和异常输入加边界校验 |
| 现实码输入 | `wx.scanCode` + `scanner`/`scan-label` | 用户主动触发；按一维码/二维码建标或填入；取消/失败不改原稿，不记录扫描原文 |
| Web BLE/原适配层 | 微信 BLE API + `BleSession` | 服务/特征发现、notify、MTU 和连接生命周期平台化 |
| NIIMBOT 协议 | `PrinterClient`/print plan/protocol | 保持协议任务与机型 profile，拒绝混用 ESC/POS 流控 |
| localStorage 旧数据 | schema v2 键空间 | 一次性迁移、归一化、限额、备份/恢复 |

## 6. 资源与包体策略

- 只保留打印/缩略图需要的像素信息，模板图转为一位 PNG；源资源不得重复放入目标包。
- 资源同步由确定性脚本执行；每次同步记录文件数、总字节、缺失引用和变更摘要。
- 主包目标不超过平台限制的 90%，当前本地目录大小只是预估，不等于上传包大小。
- 如果后续功能突破余量，优先：删除重复/不可达资源、进一步压缩、按真实使用频率拆分分包；不得通过降低错误检查换体积。
- 资源清单需标注自有、开源、经授权或待授权；待授权资源不能进入生产版本。

## 7. 开发工作流与质量门禁

每个功能变更按以下顺序闭环：

1. 更新需求与验收标准，标出涉及机型、系统和数据迁移范围。
2. 为纯逻辑先补 Node 测试；页面行为补静态事件检查和开发者工具冒烟用例。
3. 实现后执行全量测试、JSON/JS/WXML 静态检查、资源引用和包体检查；输出只绑定冻结候选 commit。
4. 通过微信开发者工具编译、预览和真机调试；涉及扫码需验证 Android/iOS 相机授权/取消/拒绝/恢复，涉及 BLE/打印必须走对应实机矩阵。
5. 由非实现者执行关键旅程回归，保存构建号、设备、固件、纸张和照片/日志证据。
6. 体验版灰度，观察连接/打印失败和用户反馈；满足退出条件后全量。
7. 生产观察窗口结束后复盘，关闭临时开关和遗留问题。

分支合并条件：无开放 P0；P1 必须修复或有明确负责人、到期时间和业务签字；不得提交 AppSecret、生产用户数据或未脱敏 BLE 日志。

## 8. 数据迁移与恢复方案

- 首次启动读取 storage version；低于 2 时复制并规范化旧文档、旧模板和默认 profile。
- 新数据先写入 v2 键并验证可读，再清理旧键；迁移过程应具备幂等性。
- 迁移失败保留旧键并提示导出/联系客服，不继续写入空数据。
- 恢复备份时先解析、检查版本与所有文档宽高/元素类型，在用户确认后覆盖。
- 发布前用四类样本演练：正常旧数据、缺字段、未知元素、接近存储上限；每类记录前后项目数和校验摘要。
