# 精臣标签小程序测试计划

文档状态：执行基线
版本：1.0
更新日期：2026-08-11

## 1. 测试目标

验证小程序不仅能展示复刻界面，还能在真实微信运行环境中安全完成模板使用、相机扫码建标/填入、编辑、保存、批量数据、BLE 连接和物理打印。测试分为可在仓库内自动执行的工程验证，以及必须由正式 AppID、微信开发者工具、真机和打印机完成的平台/硬件验证。

禁止用模拟 BLE 单测替代物理打印结论，也禁止用本地目录体积替代微信上传包检查。

## 2. 环境与证据要求

每次候选版本记录：Git commit、构建时间、微信基础库版本、开发者工具版本、AppID 环境、手机型号/系统、微信版本、打印机型号/设备名/固件、耗材尺寸和类型、测试数据版本。

证据至少包括：命令输出、开发者工具编译截图、体验版二维码/版本、关键流程录屏、打印样张照片、脱敏 BLE 阶段日志、缺陷链接和复测结果。样张照片旁放毫米尺或标准网格，便于核对尺寸与方向。

环境分层：

| 环境 | 用途 | 数据/设备 | 允许动作 |
| --- | --- | --- | --- |
| Node 本地 | 纯逻辑、协议、仓储单测 | 内存存储和 BLE mock | 可重复自动执行，不连接真实设备 |
| 微信开发者工具 | 编译、页面、权限 API 兼容 | 测试数据、模拟器 | 不作为 BLE/打印最终证据 |
| 体验版真机 | iOS/Android 旅程与硬件验证 | 专用测试打印机/耗材 | 可执行连接、诊断和打印 |
| 生产灰度 | 最小生产验证 | 授权测试账号/设备 | 只做预先批准的安全冒烟，不导入真实敏感标签数据 |

## 3. 自动化测试范围

### 3.1 领域与协议

- 文档元素默认值、克隆、边界钳制、旋转命中、几何变换、撤销/重做。
- 文本方向/样式、边框、表格、日期链接、序列号、素材和图片缓存。
- EAN-13、Code 128、二维码合法性与打印点分辨率边界。
- 栅格编码、RLE、方向旋转、字节对齐和不同机型打印计划。
- NIIMBOT 帧编码/解析、拆包/粘包、校验错误恢复、握手状态机。
- BLE 超时、错误回调、MTU 分包、特征优选、断线竞态和已有系统连接复用。
- 连接管理的单飞、TTL、僵尸连接、强制重连、kill switch、断线失效、诊断和自动重连。

### 3.2 产品数据

- 189 模板计数、ID 唯一、分类/行业筛选和全部模板文档构建。
- 10 类元素的保存/恢复与旧数据默认值填充。
- schema v1→v2 迁移幂等、项目/模板/历史限额、深拷贝和存储失败。
- CSV 引号、逗号、换行、BOM、空字段、非法行、导入/导出往返。
- 数据字段绑定、批量序列、日期偏移和异常行定位。
- 备份/恢复的版本、损坏 JSON、未知元素、不合法尺寸和覆盖确认。

### 3.3 静态与包体

- 所有 JS 可解析，JSON 可解析，WXML 中事件处理器在对应 Page 中存在。
- app.json 页面、WXML/WXSS/JS/JSON 组合完整，无丢失资源引用。
- 不包含 `eval`、AppSecret、私钥、真实用户数据或明文生产设备日志。
- 主包、分包和总包符合微信限制，并预留 10% 余量。

### 3.4 冻结候选的自动化证据

- 主线仍可能新增测试与文件，本文不固化测试数、测试文件数、JS/JSON/WXML 数、事件绑定数、资源引用数或主包字节。
- 候选 commit 冻结后执行 `npm run verify`，把完整原始输出、commit 和时间附到验收记录；其中的静态检查与测试必须全部通过。
- 同一 commit 执行 `npm run test:coverage` 并归档最新行/分支/函数结果，不沿用开发过程中的旧百分比。
- 本地包体只作预警；正式结论必须来自微信开发者工具上传报告。Node 覆盖率不包含 WXML 真实交互、微信基础库、相机扫码、Canvas 真机或实体打印。

## 5. 真机/打印机覆盖矩阵

最低发布矩阵如下；每个单元格都要执行 BLE-001、BLE-003、PRT-001（可用纸型）、PRT-002 和一次冷启动重连。`必测` 不能用同族另一型号替代；`扩展` 在有目标市场或设备库存时纳入。

| 手机平台 | D11 | D110 | B1 | B21/B21_L2B | B21_C2B | B21S/B21S_C2B |
| --- | --- | --- | --- | --- | --- | --- |
| Android 低端/Android 10–11 | 必测 | 必测 | 必测 | 必测 | 扩展 | 扩展 |
| Android 主流/Android 13–15 | 必测 | 必测 | 必测 | 必测 | 必测 | 必测 |
| iPhone/iOS 16–17 | 必测 | 必测 | 必测 | 必测 | 扩展 | 扩展 |
| iPhone/iOS 18+ | 必测 | 必测 | 必测 | 必测 | 必测 | 必测 |

每台打印机额外记录：协议 profile 判定、模型 ID、固件版本、服务/写/通知特征、协商 MTU、标签宽高、纸张类型、浓度和电量。D11/D11S 若存在新旧协议固件，两者必须分别测试；B21_C2B 和 B21S 不得仅因名称近似沿用 B21 结论。

打印内容检查：

- 40×12 mm 和 40×30 mm 基准样张；再测该机型打印头边界的精确宽度。
- 四角定位标、1 mm 网格、横竖文字、最小字号、细/粗线、旋转元素、黑白反相。
- EAN-13 和 Code 128 用至少两种扫码器/手机扫码；二维码含中文与较长内容。
- 扫码建标分别验证相机授权、取消、拒绝/恢复以及从相册识别（平台支持时）；打印样张由独立扫码器读回并与真值比对。
- 1、3 份和批量多页；核对不多打、不少打、间隙/黑标定位一致。
- 断线场景在发送前、首行后和多页中间分别执行，确认历史状态与物理结果一致。

## 6. 回归套件

### 每次提交

- 受影响模块单测。
- JS/JSON/WXML/资源静态检查。
- 相关页面开发者工具冒烟（具备 AppID 后）。

### 候选版本

- 全量 Node 测试必须 100% 通过。
- 189 模板构建、10 元素往返、迁移/备份、打印预检全量自动化。
- 首页主旅程、模板/项目/数据/我的、编辑器关键动作手工回归。
- Android 和 iOS 各一台 × 本次改动涉及的每个打印 profile。
- 上传包大小、权限/隐私、敏感信息扫描。

### 发布版本

- 执行完整真机矩阵；失败项修复后重跑该 profile 的所有平台组合，而非只复测单点。
- 体验版连续运行至少一个业务日，完成规定打印量，无开放 P0/P1。
- 生产灰度只执行安全冒烟；对任何打印失败率异常立即停止扩量。

## 7. 缺陷分级与退出标准

| 等级 | 示例 | 处理 |
| --- | --- | --- |
| P0 | 数据丢失、错打/重复大量标签、无法启动、主流程断裂、隐私/授权问题、任一必测机型不可打印 | 停止发布；修复并全量相关回归 |
| P1 | 部分模板/元素不可用、频繁重连、可恢复但严重误导、明显性能/兼容问题 | 上线前修复；例外需业务和 QA 双签、有到期时间 |
| P2 | 非关键视觉差异、低频文案或便利性问题 | 可列入后续版本，不影响正确性 |

退出条件：自动化全绿；开发者工具 0 编译错误；所有 P0/P1 必测用例通过；真机矩阵有完整证据；正式 AppID、隐私、类目和资源授权完成；灰度指标在阈值内；回滚版本与负责人已确认。

## 8. 生产安全验证

- 生产只用专门测试项目和无敏感内容的测试标签，不恢复本地测试备份到真实用户设备。
- 单次只打印 1 张明显标注“上线冒烟”的标签；不得在生产执行 300 张压力测试。
- 诊断模式不得发送打印行；日志不得包含完整设备 ID、标签内容、条码/二维码值或图片。
- 如需统计，先完成隐私声明和用户授权；在此之前以体验版人工记录为准。
