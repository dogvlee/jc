# 商跃标签登录接入

协议版本：2026-10-15。

本项目使用用户自有的 HTTPS 账号服务接入微信手机号登录。账号用于识别身份；标签、模板、图片、批量数据和打印历史仍保存在本机，登录不等于云同步或云备份。没有接入短信、邮箱、会员或支付，也不使用参考项目 `D:\vibecode\print` 的业务数据库。

用户已确认使用自有云服务器。已补齐单台 Linux 云主机的 Compose、宿主机 Nginx HTTPS 示例及持久卷说明，见 [云服务器部署](../server/README.md#自有云服务器部署)。实际服务器地址、系统和域名待提供后再接入，当前未进行远程部署。

## 自有服务与配置

用户尚未提供账号服务地址 `apiBaseUrl`。配置保持为空，不填其他项目服务或虚构地址，也不能将本地页面完成视为真实登录已可用。未配置时按钮直接提示服务未开通，不请求手机号授权。本项目已实现独立后端，启动、环境变量、接口与数据库说明见 [server/README.md](../server/README.md)。

1. 使用有权限的真实小程序 AppID `wxba51f65eb2f643e7`，核对自有账号服务实际绑定的小程序身份。
2. 在 `miniprogram/config/auth.js` 配置账号服务的 HTTPS `apiBaseUrl`；协议版本使用 `consentVersion: '2026-10-15'`。该地址对应本项目 `server` 后端，不复用其他项目未经核对的接口。
3. 在该 AppID 的微信后台配置账号服务所用的合法 HTTPS 请求域名，并确认手机可以访问、证书正常。
4. 手机号由自有服务端通过微信提供的接口获取，服务端应核验可信微信身份和小程序身份。微信应用密钥只在服务端配置，不能写入小程序代码、普通日志或提交到仓库。
5. 客户端先取得 `wx.login` 的 `loginCode`，再把用户主动授权的 `phoneCode`、`consentAccepted: true` 和 `consentVersion: '2026-10-15'` 发到 `POST /api/auth/wechat/phone`。服务端校验微信身份、手机号授权及协议版本后才建立会话。

账号资料仅保留随机账号 ID、脱敏手机号、可信微信 AppID/OpenID、协议同意时间与版本，不保存完整手机号，不接收标签业务内容。客户端在独立 auth 存储保存随机会话令牌及到期时间，服务端 SQLite 只保存令牌 SHA-256 哈希、账号引用和过期时间。有效期默认 30 天；`GET /api/auth/session` 验证会话，`POST /api/auth/logout` 撤销当前令牌，失效会话返回 HTTP 401。

不得把完整手机号、一次性取号凭证、微信用户标识、会话令牌或完整登录响应写入普通日志、截图或代码仓库。账号状态和令牌不能混入业务仓储设置与 JSON 备份。

## 小程序后台准备

在 `wxba51f65eb2f643e7` 对应的微信后台按实际功能配置手机号隐私声明，说明用途为账号识别，并核对手机号获取能力、用户隐私保护指引及登录页实际文案一致。上线负责人应检查微信后台登记的运营主体，以及手机端「··· → 小程序详情」展示的主体信息；协议只引导查看这些真实信息，不填占位主体、电话号码或邮箱。

联系途径统一引导为微信右上角「··· → 反馈与投诉」，具体菜单以微信版本实际展示为准，用于咨询、反馈和提出账号信息处理请求。本轮没有提供应用内账号删除功能；不要把退出登录描述成删除账号，或承诺点击退出后账号资料一并删除。

登录页应允许先打开用户协议和隐私说明，勾选同意后再由用户主动点击微信手机号登录。阅读协议不能自动勾选、登录或触发取号。协议页入口为 `pages/legal/index?type=terms` 和 `pages/legal/index?type=privacy`，版本统一为 `2026-10-15`。

## 本机数据规则

- 登录、登录失败、取消、退出及换账号均不迁移、清空或覆盖现有标签、模板、图片、批量数据、打印历史、编辑草稿及打印机设置。
- 账号登录态使用独立存储，不放进业务设置和 JSON 备份；恢复业务备份不能恢复其他人的账号身份。
- 退出登录清本机账号登录态，并请求账号服务撤销当前会话，账号资料仍保留。共用手机时，其他使用者仍可能访问本机内容，界面需要说明这一点。
- JSON 备份不包含本地图片文件本体，不承诺跨设备完整恢复图片。

## 本地验证

`npm run verify` 覆盖客户端、页面、服务端及 HTTP 集成测试并构建公开包。HTTP 集成使用真实客户端、HTTP 服务、SQLite 和微信响应解析，只替换微信传输，不调用真实微信。

已安装微信开发者工具并开启 CLI 调用后，可运行独立登录 UI 检查：

```powershell
$env:WECHAT_DEVTOOLS_CLI = 'D:\software\微信web开发者工具\cli.bat'
npm run test:wechat:auth
```

脚本创建独立游客项目，检查未登录入口、默认未同意、协议往返、原生勾选、服务未配置提示及返回流程。授权取消事件和已登录展示状态由测试注入，仅用于 UI 验证；没有真实取号或账号登录。结果与截图保存在 `artifacts/wechat-auth-smoke/run-*/`，不上传或发布小程序。

## 真机验收

确认自有服务接口并完成配置后，使用这个 AppID 的体验版在真机执行：

1. 未登录打开「我的」，先查看两份协议，再返回登录页；返回不能自动同意或取号。
2. 未同意时不能提交登录；拒绝手机号授权、网络失败或服务端报错后可重试，不能显示假登录成功。
3. 主动同意并授权手机号后，确认请求目标为配置的自有 HTTPS 账号服务，页面只显示脱敏手机号。
4. 退出、重新进入、重启及登录中途离开页面，确认状态正确；旧请求晚到不能恢复已经退出的登录态。
5. 登录前建立标签、带图片模板、批量行、打印历史和未保存草稿，登录与退出后逐项核对；保持现有蓝牙连接与打印流程。
6. 在自有服务核对账号资料和日志，确认没有完整手机号和标签业务内容；核对账号身份校验及访问权限。
7. 验证刘海屏、普通屏和大字号下的协议阅读、同意区、手机号按钮及返回操作，记录真实设备与结果。

本地单元测试和静态检查不能替代真实 AppID 的取号授权、自有 HTTPS 接口和手机验收。当前 `apiBaseUrl`、服务端密钥及真实部署仍待提供或完成，应明确标记「登录服务待配置」，不能宣称已正式上线。
