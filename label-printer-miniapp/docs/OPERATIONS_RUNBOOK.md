# 精臣标签小程序运营与故障处置手册

文档状态：候选版运行手册；生产值守体系待建立
适用版本：`1.0.0-rc.1`
更新日期：2026-08-11

## 1. 范围与运行边界

本文用于处理启动、BLE 连接、打印、存储、包体和资源问题，以及候选版/生产事故。它不替代 `TEST_PLAN.md` 的验证矩阵，也不把 mock 测试视为真机结论。

当前运行边界：

- 产品本地优先，没有账号、服务器、云同步或远程遥测。
- 标签、项目、模板、批量数据、历史、设备绑定和用户图片保存在微信本机沙箱。
- 连接链路为微信 BLE API → E781 GATT 服务 → NIIMBOT `0x55` 协议，不是 ESC/POS。
- 自动化已覆盖连接状态机和打印协议；微信运行时、手机蓝牙栈、固件和纸张仍必须依靠真机证据。
- 事故发现目前依赖测试人员、用户反馈和人工汇总。未完成隐私披露前不得临时上传标签内容或设备标识做诊断。

## 3. 事故分级

以下响应时间是建议目标，需由团队正式确认后才成为 SLA。

| 等级 | 判定示例 | 建议响应 | 发布动作 |
| --- | --- | --- | --- |
| SEV-0 | 隐私泄露、凭据泄露、大范围错误/重复打印、不可恢复数据损坏、无授权内容已外发 | 15 分钟确认，持续指挥 | 立即冻结/撤回；法务与负责人同步 |
| SEV-1 | 正式版无法启动、主流机型普遍不可连接/打印、恢复导致数据风险、P0 主旅程中断 | 30 分钟确认 | 停止灰度，准备回滚 |
| SEV-2 | 单一机型/固件或部分模板失败，有安全绕行；存储接近上限 | 4 小时内评估 | 暂停相关范围，修复候选 |
| SEV-3 | 非关键视觉、文案、低频便利性问题 | 下一工作日归档 | 可进入计划版本 |

无论发生比例多小，数据丢失、错打/重复打印、隐私和授权问题均至少按 SEV-1 处理；涉及真实外泄或广泛影响升级为 SEV-0。

## 4. 首次响应通用流程

1. **先止损**：停止重试、批量打印和继续放量；不要让用户清空微信数据。
2. **判定阶段**：区分页面/存储、相机扫码、BLE 设备扫描、GATT、协议握手、打印预检、数据发送、打印机硬件和完成确认。
3. **固定范围**：记录版本/commit、环境、手机/系统/微信、打印机/固件、耗材、首次时间和发生比例。
4. **保存脱敏证据**：错误文案/码、诊断阶段、MTU、机型 ID、连接路径、样张照片；设备 ID 仅留散列或末四位。
5. **选择处置**：用户可安全绕行则说明；否则冻结版本、启用受控止损或回滚。
6. **验证恢复**：原复现场景 + 相邻机型/平台 + 单张安全冒烟，不只验证一个 happy path。
7. **结案**：记录根因、防复发测试、数据处理、影响用户和后续负责人。

禁止在证据中记录完整标签正文、条码/二维码、用户图片、完整蓝牙地址、备份文件、AppSecret 或上传私钥。

## 5. 健康信号与诊断

连接管理器状态包括 `disconnected`、`connecting`、`connected`，并记录连接来源和错误。正常链路至少满足：

1. 蓝牙适配器可用。
2. 目标设备可发现或可从系统连接恢复。
3. E781 服务及指定 write/notify 特征存在。
4. 通知已启用，MTU/最大写入长度有效。
5. NIIMBOT 协议握手完成，`PrinterClient.ready === true`。
6. 机型 ID/协议版本能映射到明确 profile，或由用户明确确认准确型号。

编辑器“连接诊断”会调用 `PrinterConnectionManager.diagnose()`，返回适配器、系统连接、GATT、协议、MTU、机型 ID 和连接路径。诊断不会发送打印行，但可能重建连接并执行握手；必须在没有正在打印的任务时使用。

## 6. 故障处置

### 6.1 小程序无法启动、白屏或页面缺失

**检查**

1. 确认版本和环境，是否为已验收 commit。
2. 在干净 checkout 执行 `npm ci && npm run verify`。
3. 查看开发者工具编译 error、基础库版本和 `app.json` 页面完整性。
4. 区分全部用户、单一系统、单一字体/屏幕或仅旧本地数据。

**处置**

- 自动化失败：停止发布，修复后全量重跑。
- 微信编译失败但 Node 全绿：保留 DevTools 错误和基础库信息，不把静态检查当平台通过。
- 仅旧数据失败：先导出备份或复制测试数据复现；禁止要求真实用户直接清空数据。
- 正式版主流程不可达：按 SEV-1 回滚上一已验证版本。

### 6.2 相机扫码建标或扫描填入失败

**检查顺序**

1. 确认用户是主动点击首页“扫码建标”或编码元素“扫描填入”，不是小程序启动时弹出相机。
2. 区分用户取消、相机权限/平台失败、空/超长内容和一维码/二维码类型不匹配；取消不作为事故或错误弹窗。
3. Android/iOS 分别检查微信相机权限、系统限制与当前微信版本；从系统设置返回后重新由用户触发。
4. 首页扫码失败时确认没有创建草稿；编辑器扫码失败时确认原元素值、撤销栈和自动保存未被改变。
5. 一维码检查 EAN-13/Code 128 的长度、校验位和可打印 ASCII；二维码保留 UTF-8，但仍需通过尺寸与打印预检。

**隐私与处置**

- 不记录扫描原文、`rawData` 或原始图像，不把扫码内容复制到事故日志、工单或遥测。
- 使用合成测试码复现；需要比对时只记录码型、长度桶、错误码和脱敏真值编号。
- 扫码成功不代表可打印，也不得自动连接或出纸；用户应先在编辑器确认并通过预检。

### 6.3 BLE 扫描不到打印机

**检查顺序**

1. 打印机开机、有电、未被其他手机占用，并靠近手机。
2. 手机蓝牙已开启；Android 同时检查系统定位服务状态和微信权限提示。
3. 关闭其他正在扫描的页面，重新打开设备列表；代码会先停止旧扫描再开始新扫描。
4. 确认设备广播名称非空。当前列表只展示有名称的设备。
5. 在另一台已知正常手机/打印机交叉验证，区分手机栈和打印机问题。

**不要做**

- 不要因名称相似就选择错误 profile。
- 不要把任意 FF00/FF02/FF03 ESC/POS 设备当作 NIIMBOT 设备。
- 不要在用户未主动连接时持续扫描。

### 6.4 能发现但连接或握手失败

**检查顺序**

1. 执行“连接诊断”，记录失败在适配器、系统连接、GATT 还是协议阶段。
2. 核对服务为 E781，write/notify 特征为项目定义的主特征，MTU 不为 0。
3. 若系统显示已连接但 GATT/协议失败，选择“忘记打印机”后重新扫描；连接管理器会关闭僵尸链路再发现。
4. 记录机型 ID、协议版本和固件；未知 ID 必须阻断打印，不能套用相似型号。
5. 在 Android/iOS 各一台和同型号另一固件交叉验证。

**常见分类**

- `DEVICE_INCOMPLETE`：没有可用设备 ID，重新扫描选择。
- `CONNECT_BUSY`：已有另一台设备正在连接，等待当前连接结束。
- `BLE_RECONNECT_OFF`：稳定连接管理器被本地开关关闭；人工选机仍可能走直接连接。
- 协议协商失败：GATT 已通但目标不是受支持协议、固件不兼容或通知异常。
- 未知型号 ID：链路可用但 profile 无硬件证据，保持文档并阻断打印。

### 6.5 频繁断线、假连接或自动重连风暴

1. 停止正在进行的批量打印，记录断线发生在发送前、首行后还是多页中间。
2. 检查连接来源：`fast-reuse`、`system-reuse`、`rediscovered`、`zombie-recovered` 等。
3. 使用“忘记打印机”清除持久绑定，再人工扫描；不要只改页面上的“已连接”文案。
4. 检查打印机电量、手机后台限制、距离和并发连接。
5. 若自动重连持续放大故障，在受控设备启用第 7 节 kill switch；它不会远程影响其他用户。
6. 修复后执行蓝牙开关、前后台、杀进程、僵尸连接和切换两台打印机的完整回归。

### 6.6 打印按钮被预检阻断

这通常是安全行为，不是 BLE 故障。按提示检查：

- 未确认准确机型。
- 标签为空或仍含默认占位内容。
- 标签尺寸超过打印头能力。
- 条码字符/校验位错误、二维码过小、元素尺寸非法。
- 画布尚未就绪或图片仍未加载。

修改文档或选择有硬件证据的兼容 profile 后重新预检。不得通过关闭校验、裁切或静默缩放绕过。

### 6.7 打印失败、部分出纸或疑似重复打印

**第一原则：已开始发送后不自动重试。** 失败记录只能说明软件未确认完成，纸上可能已经输出部分内容。

1. 立即停止用户反复点击和批量任务，检查纸面实际结果。
2. 记录失败阶段、历史中的 `failed/cancelled`、份数、最后进度、机型/固件和样张。
3. 打印机错误按类型处置：

| 错误组 | 典型信息 | 操作 |
| --- | --- | --- |
| 耗材/机械 | 上盖未关、缺纸、走纸异常、未装碳带、纸张类型不匹配 | 修复硬件/纸张后，由用户明确确认是否重印 |
| 电量/温度 | 电量过低、电池异常、打印头过热/过冷 | 停止任务，充电或等待恢复；不得连续重试 |
| 状态 | 打印机忙、任务取消、接收超时 | 等待/重连并核对纸面，再决定剩余页 |
| 数据/参数 | 打印数据、画布参数、标签页参数不合法 | 视为代码/配置缺陷，保存文档，禁止绕过 |
| 通信 | 通信异常、已断开 | 先确认物理输出，再重建连接；不自动整批重放 |

4. 用户点击取消只会停止后续命令，并尝试发送取消命令；已经下发的数据仍可能出纸。
5. 任何重复打印或份数错误至少按 SEV-1，冻结相应 profile 的放量并回归 1/3 份、批量和断线时机。

### 6.8 本地保存失败或存储接近上限

仓储写失败会返回“本地存储空间不足”，项目/模板/历史上限分别为 120/80/80，数据行最多 1000；最近 10 条历史保留文档副本。用户图片文件另存于 `USER_DATA_PATH`，当前没有自动清理机制。

处置顺序：

1. 停止继续添加图片或批量生成。
2. 若仍可操作，先导出 JSON 备份和必要 CSV，并让用户自行保管。
3. 由用户在 UI 中删除不再需要的项目/模板；不要直接改存储键或清空微信数据。
4. 重新保存一个小项目验证写入。
5. 若图片持续占用，登记为产品缺陷；当前版本没有安全的孤儿图片清理入口，不建议客服远程指导修改沙箱文件。

### 6.9 备份恢复失败

1. 确认备份版本、文件来源、大小和是否被截断；只用副本排查。
2. `RESTORE_FAILED` 表示恢复中断但原数据已回滚保留，可以修复输入后再试。
3. `RESTORE_ROLLBACK_FAILED` 是高危状态：停止编辑和二次恢复，保留原备份与设备，由开发/数据负责人处理。
4. 不要反复覆盖恢复，不要把 QA 备份导入生产用户设备。
5. 复现必须覆盖项目、模板、设置、数据和历史的多键中途失败，而非只测 JSON 可解析。

当前模板导入有 2 MiB 限制，但 CSV 和完整备份导入尚无文件大小前置限制；超大文件导致的内存/存储问题应作为缺陷记录，不应要求用户继续尝试。

### 6.10 包体超限或资源缺失

执行：

```powershell
npm run check
```

检查输出中的 JS/JSON/WXML、事件绑定、静态资源和主包字节。处置顺序：

1. 找到新增或变大的资源，不直接降低校验阈值。
2. 确认资源确实可达、有授权且无重复；优先删除不可达/重复内容。
3. 素材变更经批准后才运行 `npm run assets:sync`，并比较输入、输出数量和哈希。
4. 优化脚本不会主动清理历史遗留文件；删除前必须有资源引用检查和代码评审。
5. 本地通过后仍需以微信开发者工具上传包报告为准。

资源缺失时保留模板可编辑和占位反馈，但发布候选必须修复所有静态引用；不得让 404/缺图静默进入正式版。

## 7. BLE kill switch 操作

`ble_reconnect_off` 是本机持久键，只阻止 `PrinterConnectionManager.ensureReady` 和自动重连路径。编辑器人工选择设备遇到该错误时会回退到直接 `PrinterClient.connect`，因此它不是“禁用全部打印”的总开关，也不是远程开关。

仅在 QA/受控设备、没有正在打印的任务时操作。建议通过开发者工具控制台使用管理器 API：

```javascript
(async () => {
  const manager = getApp().globalData.connectionManager;
  manager.disable();
  await manager.disconnect();
})();
```

恢复：

```javascript
getApp().globalData.connectionManager.enable();
```

也可用 `wx.setStorageSync('ble_reconnect_off', true)` / `wx.removeStorageSync('ble_reconnect_off')` 控制下次启动，但必须记录设备、操作者、时间、原因和恢复验证。

限制与注意：

- `disable()` 不会取消正在进行的打印，先在 UI 请求取消并核对纸面。
- 该开关不会下发给已安装用户，无法作为生产全量止损工具。
- 若必须彻底阻止受影响版本打印，应冻结放量、通知用户停止操作并走版本回滚/修复。
- 恢复开关不会删除已保存设备；恢复后仍要跑僵尸连接和单张打印验证。

## 8. 证据与日志脱敏

### 可以记录

- 候选版本、commit、环境、时间、阶段、错误码和耗时。
- 手机型号、系统/微信版本；打印机机型族、固件、协议版本。
- MTU、write 类型、连接来源；服务/特征 UUID 可用于工程诊断。
- 设备 ID 的不可逆散列或末四位。
- 使用合成内容的截图、录屏和样张。

### 禁止记录

- 完整设备 ID/蓝牙地址、序列号和用户身份映射。
- 标签正文、条码/二维码值、CSV 行、用户图片和完整备份。
- AppSecret、上传私钥、平台 cookie/token。
- 未经许可的第三方模板原文件或生产用户数据。

当前没有集中日志组件；如后续增加遥测，必须先定义事件字典、字段白名单、保留期、访问控制和隐私披露，再进入开发。

## 9. 日常运行检查

### 每个候选版本

- `npm ci`、`npm run verify`、覆盖率、包体和资源检查。
- 开发者工具编译/预览，主旅程和所有错误态冒烟。
- Android/iOS × 受影响打印 profile 真机验证。
- 迁移、备份、恢复失败回滚和单张打印。
- 秘密、隐私声明、依赖 notice、品牌和素材授权复核。

### 每次资源刷新

- 输入来源/授权、转换工具版本、文件数/字节、引用完整性。
- 189 模板构建、随机缩略图/素材视觉抽样、微信上传包体。
- 清单中不存在无用上游 URL、用户标识或调试元数据。

### 每次事故后

- 受影响需求对应的自动化测试。
- 至少一个相邻平台/机型回归。
- Runbook 与 traceability 状态更新。
- 根因、检测缺口、止损有效性和负责人/到期时间。

## 10. 已知运营缺口

- 没有正式 AppID、开发者工具/体验版/真机证据。
- 没有远程遥测、远程配置或全量停印开关。
- 本地 kill switch 没有用户 UI，且人工选机会回退直接连接。
- 没有用户图片孤儿文件清理、存储用量仪表或“一键清除本地数据”。
