# 架构决策记录

## 使用方式

本文记录影响长期演进和安全边界的关键决策。状态分为“已采纳”“候选”“已否决”。修改已采纳决策时，应追加新决策并说明替代关系，而不是删除历史。

## ADR-001：采用微信原生小程序实现

- 状态：已采纳
- 决策：页面使用 WXML、WXSS 和小程序 Canvas，领域模块使用 CommonJS；不以 WebView 包装原 Web 应用。
- 原因：BLE、相册、文件、前后台生命周期和上传审核均依赖小程序原生能力。
- 代价：浏览器 UI 不能直接复用，必须重新实现交互并进行双平台验证。

## ADR-002：业务数据本地优先

- 状态：已采纳
- 决策：项目、用户模板、设置、批量数据、打印历史和设备绑定保存在 `wx` 本地存储；当前不引入账号和云端同步。
- 原因：降低首版依赖和隐私面，离线仍可编辑与打印。
- 代价：卸载或清理存储会丢失数据；跨设备同步不在当前范围，用户必须主动导出备份。

## ADR-003：BLE 会话由应用级单例拥有

- 状态：已采纳
- 决策：`App.onLaunch` 创建唯一 `PrinterConnectionManager`，页面卸载只退订，不关闭全局适配器。
- 原因：微信 BLE 回调是进程级资源，多页面实例会造成监听争用、假连接和重复重连。
- 代价：需要显式管理生命周期、手动断开意图和连接代次。

## ADR-004：只允许已知 NIIMBOT GATT 通道

- 状态：已废止（2026-10-07 被 ADR-013 取代）
- 决策：发现时优先并校验 E781 服务、已知 write/notify 特征，或此前持久化且已验证的通道；普通“可写特征”不足以进入 ready。
- 原因：避免向无关 BLE 外设发送私有协议字节。
- 代价：新硬件必须先验证并加入 profile，不能以宽松发现方式自动兼容。
- 废止原因：该规则要求 E781 服务里另有 `…9f9e` 通知特征，但这个 UUID 没有真机证据。开源实现（以及 RC1 之前的本仓库代码）都在被写入的 `…9f9f` 特征上收通知，严格校验会把真实打印机判成“不是支持的标签打印机”。

## ADR-005：协议帧完整写入，不按 MTU 任意切分

- 状态：已采纳
- 决策：每个 NIIMBOT `55 55 ... AA AA` 帧作为一次 GATT write；若 MTU 不能容纳则明确失败。
- 原因：打印机协议按完整帧消费，任意切分会破坏帧边界。
- 代价：低 MTU 环境不能靠通用分包绕过，必须调整计划或确认设备能力。

## ADR-006：打印中断后不自动重放

- 状态：已采纳
- 决策：连接可以自动恢复，但一旦发送过打印行，失败后不自动重发整张或整批。
- 原因：应用无法可靠判断打印机已经消费了多少内容，自动重放可能产生重复标签或半张标签。
- 代价：恢复操作需要用户检查实物并确认手动重打。

## ADR-007：打印机适配不修改用户原稿

- 状态：已采纳
- 决策：编辑预览可以保留任意有效标签尺寸；打印前由 `evaluatePrintability` 给出阻断和可用机型建议。
- 原因：静默缩放或裁切会损坏用户设计和条码可读性。
- 代价：部分设计在当前设备上只能编辑、不能打印。

## ADR-008：不接入 FF00/FF02/FF03 ESC/POS 流控

- 状态：已否决；ESC/POS 打印部分由 ADR-014 取代（FF03 信用令牌高速模式仍不接）
- 决策：当前 NIIMBOT 路径不使用 ESC/POS `GS v 0` 或 FF00 信用令牌协议。
- 原因：服务 UUID、帧格式和背压语义均不同，直接复用会选择错误特征并写入错误字节。
- 后续：若支持该类打印机，应建立独立 transport/profile 家族，不与 NIIMBOT 会话混用。

## ADR-009：首版将模板与素材随包离线发布

- 状态：已采纳
- 已废止的早期决策：把 190 套模板及相关黑白素材直接打入公开主包。当前完整目录只保留在内部开发根；公开上传目录必须物理排除第三方内容，并通过 `scripts/check-shangyue-release.mjs`。
- 原因：避免网络依赖，保证模板浏览和编辑的确定性。
- 代价：主包余量有限；新增素材必须压缩、评估分包，并先确认再分发权利。

## ADR-010：候选型号映射必须经过真机门禁

- 状态：已废止（被 ADR-013 取代）
- 决策：`2320 → d110`、`4098 → b1` 可参与代码和 mock 测试，但在对应固件真机验证前不得作为正式支持承诺；B21 Pro `D110M_V4` 当前阻止适配。
- 原因：型号 ID 与任务族的映射来自推断，不足以替代打印样张和错误恢复验证。

## ADR-011：扫码使用微信原生能力并保持本地、显式触发

- 状态：已采纳
- 决策：首页扫码建标和编辑器扫码填入通过 `wx.scanCode` 的服务封装调用；仅在用户点击时触发。领域层只接收结果文本与类型，取消、失败或类型不符不修改原稿，不保存原图或 `rawData`，不自动上传或打印。
- 原因：利用微信平台权限与扫码 UI，同时把不可信输入的类型、长度和打印校验留在可测试领域层，减少权限打扰和内容泄露。
- 代价：真实权限、码型和系统差异无法由 Node mock 证明，必须执行 Android/iOS 真机矩阵。

## ADR-012：标签可略大于打印头，只跳过空白边条

- 状态：已采纳（补充 ADR-007，仍不修改用户原稿）
- 决策：打印头居中于纸面。标签在打印头方向可以超出打印头，但不超过机型的最大纸宽 `paperMaxMm`（D11/D110 为标签高 15 mm，B1/B21 为标签宽 50 mm，取自公开规格，待真机确认）。`printRasterPlan` 渲染整张标签，只把居中的打印头宽度发给打印机；两侧打不到的边条只允许是空白，任何内容进入边条都阻断打印，不缩放、不裁切内容。打印前 `evaluatePrintability` 用元素外接框（含旋转和描边）预检；打印时再用 `marginInkReport` 以编码器相同的黑白判定检查实际渲染像素。
- 原因：50 mm 等常用纸宽略大于打印头，旧规则使多数场景模板在任何机型上都无法打印；而模板内容本就离纸边 ≥1 mm，边条原本是空白。
- 代价：B 系列 50 mm 纸左右各约 1.0 mm、D 系列 15 mm 纸上下各约 1.5 mm 不能放内容；公开货架只展示至少一种支持机型能打印的模板，`app/curated/printable-index.js` 须用 `npm run curated:printable` 随模板或机型配置一起更新。

## ADR-013：连上即可打印，不按型号阻断

- 状态：已采纳（2026-10-07 产品决定，取代 ADR-010）；其中精臣型号推断部分已随 ADR-015 删除，“连上就保持连接、不按型号阻断”仍然有效
- 决策：任何完成 BLE 连接和 NIIMBOT 握手的打印机都可以打印，不再因候选型号 ID（`2320`、`4098`）或未知型号阻断，也不弹窗要求确认型号。打印机上报且能直接映射的型号 ID 决定 profile（只凭蓝牙名称识别不算上报）；否则依次使用：打印机连上前在编辑器手动选的型号（连上后记为这台打印机的型号）> 用户为这台打印机选过的型号 > 最可能的型号（候选 ID 映射 → 厂商机型表按型号 ID 判断走纸方向 → 设备名称规则 → 厂商机型表按名称 → 名称首字母：D 开头按 D11/D110，B 开头按 B1）> 能放下当前标签的型号。厂商机型表取自 `research/extracted-configs/printerList.json`：侧向出纸的窄打印头（B16、B18、D101、H1 等）按 D11/D110，顶部出纸（B3S、K3、A8、B21 Pro 等）按 B1。打印弹层的“打印机型号”一行和设置页仍可改型号；对型号不确定的打印机所做的修改按设备记住，下次连接直接使用。
- 原因：用户要求“现在不要限制型号 连上就能打印”；型号门禁让大量能用的同系列打印机无法出纸，而选错型号的后果是浪费一张标签，用户可以自行改选。
- 连接层：不再要求固定的写/通知 UUID 对。按 E781 服务 → 此前用过的通道 → 其他服务的顺序，选同一服务里能写入又能通知的特征：E781 优先 `…9f9f` 写入，并优先在同一特征上收通知（没有时用 `…9f9e` 或服务内其他通知特征）；其他服务优先“既能写又能通知”的单个特征，否则取一个可写特征加一个通知特征。通用访问、设备信息、电量等基础服务（1800/1801/180A/180F）不参与。
- 连上即保持连接（2026-10-07 用户要求“绑定各式各样的蓝牙”）：蓝牙链路建立后，任何后续步骤都不再弹窗、不再断开。找不到写入+通知组合时退而用只能写入的通道，什么都写不进的设备也保持连接；通知开不了、握手（CONNECT）不回、回包无效、型号/序列号等信息查询不回、心跳不回，都只记为“未回应”（`answered: false`）。设备列表不再区分“其他蓝牙设备”，所有设备一个列表，已知打印机排前面。真正的失败只在打印时说明：没有可写通道报 `NO_NIIMBOT_CHANNEL`（“这台设备不能接收打印内容……”）；打印前会再握手一次，仍不回应报 `PRINTER_UNANSWERED`（“已经连上这台打印机，但它不回应商跃标签的打印指令”）。链路本身断开（10006/10002、断开事件、被另一次连接取代）仍按连接失败处理。
- 代价：猜错型号可能打出错位、空白或乱码的标签，需要用户在“打印机型号”中改选后重打；300 dpi 机型按 203 dpi profile 打印，输出约为设计尺寸的 2/3；打印头宽于 48 mm 的机型只打中间 48 mm；B16、A1 Pro 等 270° 出纸机型按 D11/D110 方向打印，内容可能倒置；B21 Pro `D110M_V4` 专用路径仍未适配，只按 B1 尝试。标签超过打印头的物理尺寸检查（ADR-012）仍然生效，型号只是猜测时会给出“切换为 X”的建议。

## ADR-014：不走精臣通道的打印机用 ESC/POS 打标签

- 状态：已采纳（2026-10-07 产品决定，取代 ADR-008 的 ESC/POS 部分）；ADR-015 起所有打印机都走这条路径
- 决策：按连上的服务分协议，不按名称猜。走精臣 E781 服务的照旧用 NIIMBOT 帧；其他打印机（深云达 SYD 等热敏机）一律用 ESC/POS，连接时不发任何字节，不做 NIIMBOT 握手。打标签照搬小票小程序 `D:\vibecode\print` 的稳定发送：`ESC @`、`ESC a 0`、`ESC 3 24` 开头；标签按 203 dpi 转黑白，居中放在打印头宽度上（58 mm 机 384 点、80 mm 机 576 点，按蓝牙名末尾 58/80 判断，同 `print-settings.js widthFromDeviceName`）。图像拆成多条独立的 `GS v 0`，每条最多 32 点行、1400 字节、8 个蓝牙包，条与条之间等 80 ms。打印机支持写应答时逐包写应答，否则逐包写无应答再隔 10 ms。每张标签末尾发厂家《打印指令 v1.06》第 3 章的 `GS FF`（`1D 0C`，“走纸到下一张”）走到下一张标签开头。取消只在两条之间生效，不留半条光栅。
- 型号：新增 `escpos-58`、`escpos-80`（“热敏打印机 58mm / 80mm”），`family` 为空，不参与货架的 D/B 分组；浓度用打印机自身设置，界面不显示浓度。尺寸不合适时只在同类型号之间建议切换，精臣打印机不会被建议成热敏型号，反之亦然。精臣打印机被手动选成热敏型号时，打印前直接提示换型号。
- 原因：老板的打印机是深云达 ESC/POS 热敏机。之前对它发 NIIMBOT 握手帧（`55 55 C1 …`），这些字节会被当成文字印出来（“标签指令是错的”）。`print` 小程序在同一批打印机上已经验证过 `GS v 0` 分条稳定发送。
- 代价：没有接 FF03 令牌高速模式，大标签比小票小程序的高速模式慢。ESC/POS 打印机打完不回应答，只要最后一条和走纸写成功就算完成。`GS FF` 依赖打印机处于标签/黑标模式：普通连续纸上它可能走纸到最大票长或不动，要真机确认。默认不发厂家私有的黑标检测开关（`1F 1B 1F 80 …`），因为纸上没有黑标时开着会报警。

## ADR-015：只支持 ESC/POS 热敏打印机

- 状态：已采纳（2026-10-07 老板决定“我只要支持 esc/pos”，取代 ADR-004、ADR-008、ADR-010、ADR-013 中的精臣部分）
- 背景：老板用 EY-260 实测，仍然报“不回应打印指令”，说明程序还在对它发精臣握手。原因可能是它连在 E781 服务上（这个服务不是精臣专用，很多普通热敏打印机模块也用它，按服务分协议的 ADR-014 会把它当成精臣），也可能测的是 ADR-014 之前的版本。与其再猜，不如只保留 ESC/POS。
- 决策：删除全部精臣（NIIMBOT）协议代码：`core/protocol.js`、`core/print-plan.js`、`image-encoder.js` 的行编码、`BleSession.request()` 与回包解析、`PrinterClient` 的握手、型号查询、打印计划、等待完成和取消帧，以及按型号编号、名称和厂商表推断型号的逻辑。所有打印机都按 ADR-014 的 ESC/POS 方式打印。连接时不发任何字节；打印时先发 `ESC @`，再分条发 `GS v 0`，每张后按纸张类型走纸：间隙纸、黑标纸、定孔纸用 `GS FF`，连续纸约走 20 mm（`GS P 203 203` + `ESC J 160`）。
- 型号：只剩 `escpos-58`（“58mm 打印机”，384 点，最大纸宽 58 mm）和 `escpos-80`（“80mm 打印机”，576 点，最大纸宽 80 mm）。按蓝牙名末尾 58/80 自动选，名字里没有宽度时默认 58mm；用户为某台打印机选过的型号优先。旧数据里的 `d110` 等编号读出来时按 58mm 处理。货架系列改成 5（58mm）和 8（80mm），`app/curated/printable-index.js` 已重新生成：300 套原创模板中 294 套可打印（58mm 193 套，80mm 294 套）。默认纸张改为 50×30 mm（常用价签尺寸，也是老板自己打印机用的纸）；首页推荐、场景模板和编辑器的模板列表优先显示与纸张同尺寸的模板。
- 代价：精臣 D11/D110/B1/B21 不能再打印；对它们发 ESC/POS 会打出乱码或不出纸。本次未实现 FF03 令牌高速模式和打印机状态查询，打印机缺纸、开盖不会提示；`GS FF` 需要打印机处于标签/黑标模式，待真机确认。`docs/BLE_PRINTING_PROTOCOL.md` 中的精臣章节只作历史记录。
