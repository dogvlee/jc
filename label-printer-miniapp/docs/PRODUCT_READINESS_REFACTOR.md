# 商跃标签：产品可用性与架构收口

审计日期：2026-09-16。范围：本仓库当前首页、编辑器、仓储、打印与发布配置。本文记录代码审计和本次重构的验收口径，不是微信或实物打印验收报告。

## 产品决定

**本次审计后仍不建议向普通用户正式开放；代码已完成主流程可靠性重构，可进入微信与目标设备验收。** 重构前首用默认纸张、草稿恢复和容量上限下的数据保留存在阻断主任务或丢失用户成果的问题，现已补齐对应修复与自动化回归。实际手机上的“创建 → 编辑 → 保存 → 打印 → 再次打开”仍需平台和实物验证。

判断来自实际代码和针对性复现，不沿用旧文档中“工程闭环已经形成”的表述。本次重构可以修复本地软件问题；它不能生成真实 AppID、微信审核结果或打印样张。

## 本次架构边界

保留现有首页壳和 Canvas 编辑器，抽出跨页面且会影响用户成果的业务职责。

```text
首页 / 编辑器（展示、输入、用户确认）
    ├─ 编辑会话服务（打开、草稿恢复、保存、放弃）
    │      └─ Repository（校验、容量、迁移、持久化）
    └─ 打印任务服务（冻结任务输入、状态、取消、任务结果）
           ├─ 打印机连接管理器（发现、握手、连接复用）
           └─ PrinterClient → BleSession（协议任务与传输）

core（文档、渲染、编码与机型规则）供上述业务共同调用
```

- [EditorSession](../miniprogram/services/editor-session.js) 统一解释一次性入口与持久草稿的优先级；恢复、保存成功和主动放弃是不同操作，明确反映到草稿状态。
- [Repository](../miniprogram/services/repository.js) 是用户资产的持久化边界。页面不能先显示成功再尝试写入；项目和用户模板不采用历史日志那样的静默淘汰策略。批量容量及数据校验全部通过后一次提交，失败不留下半批结果。跨键迁移与恢复通过 [RecoverableStorage](../miniprogram/services/recoverable-storage.js) 保留持久回滚日志，中断后先恢复原数据，恢复失败则停止后续读写。
- [PrintJobService](../miniprogram/services/print-job-service.js) 负责一次任务的文档、参数、结果和取消生命周期，在调用开始时同步冻结任务输入。它在连接准备、异步渲染和多页发送期间维持任务锁，返回已确认份数与可能出纸标记。编辑器使用任务报告写入历史；服务本身不持有仓储。传输完成与历史记录写入结果分别反馈，历史保存失败不重复打印。
- 连接管理器继续负责 BLE 单飞、握手和重连，打印协议保留在 `PrinterClient` / `BleSession`。页面退出或用户取消必须阻止后续发送；已发送内容可能已经出纸，不宣称撤回，也不自动整单重打。
- 应用和页面的初始化边界处理本地故障并提供重试。错误状态不能靠创建一份空文档掩盖原数据读取失败。

编辑器手动保存和首页“保存草稿并打开新标签”共用 `Repository.saveEditorProject()`：项目、clean autosave、清除旧导航草稿在同一持久事务中提交。任一步失败都保留原项目与未保存的草稿，防止旧稿复活或重试生成重复项目。

此次为主任务可靠性重构，并未完成对编辑器所有手势、素材、属性面板的全面拆分。页面较大仍是后续维护成本，但不是本次发布结论的唯一依据。

## 用户反馈与数据原则

保存、打印、批量生成分别有明确结果；不能用一个“成功”同时代表写盘成功、已向设备发送和实际完成出纸。普通用户需要知道是否还要操作、是否可以离开、失败以后如何保留成果。

恢复草稿必须可发现；不保存退出必须与后续恢复行为一致。保存上限不能通过丢掉旧标签为新标签腾位。打印失败保留文档和已知进度，提示检查实物再手动决定重打。

蓝牙告知应与行为一致：首次连接由用户主动触发；保存过设备后，冷启动和蓝牙恢复可能自动重连。审计发现旧首页“仅在主动使用对应功能时请求”的绝对文案没有覆盖后者。全新安装没有已记忆设备时，代码并不会仅因打开首页就扫描蓝牙，不应把二者混写。

JSON 备份目前包含图片路径，不包含用户图片文件本体。它不能被描述为完整的跨设备备份。字体按需联网加载和主动导入的远程图片也应与“本地保存”分开说明。

## 回归与放行边界

工程回归至少验证下列行为，结果以同一候选提交的测试输出为准：

1. 全新设置创建的空白标签与默认 profile 兼容；不修改已存标签尺寸。
2. 输入尚未失焦、系统返回、切后台和进程重启后可恢复最后编辑；恢复入口与打开已有项目不会互相覆盖草稿。
3. 达到项目 / 模板上限，以及剩余容量不足的批次，不写入、不删除旧数据，不显示成功。
4. 存储读写失败时不显示假成功，可重试；迁移或恢复中断保留原数据。
5. 首次连接后回到打印预检；连续点击、取消、页面退出、设备断开不产生重复任务或额外页面。
6. 打印文档与参数在任务开始时固定；成功、失败、取消分别记录；历史写入失败不会触发重印。

`npm run verify` 是本地工程门禁，`npm run release:shangyue` 是公开包构建及内容门禁。二者都不等于生产准入，也不验证实际权限弹窗、微信渲染或打印机样张。
