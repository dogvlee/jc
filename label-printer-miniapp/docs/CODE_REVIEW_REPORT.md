# 代码复核报告

复核日期：2026-08-11
复核对象：`label-printer-miniapp` `1.0.0-rc.1` 工程候选
结论：仓库内可自动验证的核心链路已完成复核和缺陷收口；生产发布仍被微信、真机、硬件、隐私和内容授权外部门禁阻断。

## 1. 复核范围与方法

主代理直接检查了以下代码与调用关系，而非仅采信测试汇总：

- 工程配置、依赖锁、应用入口、页面注册和静态检查脚本；
- 首页与编辑器 JS/WXML/WXSS，包括扫码、导入、模板、项目、批量、Canvas、手势、图片、预检、连接、打印、取消和生命周期；
- `core` 下文档、几何、手势、渲染、编码、模板导入、profile、协议、点阵和打印计划；
- `services` 下仓储、CSV、扫码、BLE 会话、连接管理和打印客户端；
- 189 个模板的目录/构建/几何，以及静态资源引用的程序化全量校验；
- 全部自动化测试、需求到测试追踪、风险与发布门禁。

生成型的大体积模板目录和图片二进制采用结构、引用、尺寸和可构建性全量校验；没有把“程序可读取”冒充为逐张视觉审美或素材授权审查。BLE mock 也不能替代真实手机、固件和耗材。

| CR-003 | P0 | `already connect`、僵尸连接、错误特征选择、MTU 回退、发现挂起和旧异步连接发布 | 固定可信 NIIMBOT 通道、watchdog、connection epoch、硬恢复、MTU 保留和对应模拟测试 |
| CR-004 | P0 | 连接仍在时缺纸/开盖/不支持等致命打印机错误会被打印状态重试吞掉 | 仅明确响应超时允许重试；打印机错误立即保留并抛出 |

## 3. 新功能专项复核

“扫码建标/扫码填充”经过以下规则复核：

- 原生明确的 `CODE_128` 等一维类型优先于纯数字内容推断；二维码保留原始空白；
- 一维码和二维码分别有内容长度、制式和目标元素类型保护；类型不匹配不覆盖原值；
- 新文档尺寸限制为 5–150 mm，生成元素始终在画布内；
- 首页和编辑器都做 single-flight，取消、拒绝或失败不创建/修改文档；
- 不保存扫描原图、`rawData`，也不自动联网查询或自动打印。

## 4. 自动证据与人工证据边界

候选冻结时必须重新保存以下原始输出：

```powershell
npm.cmd run verify
npm.cmd run test:coverage
npm.cmd audit --audit-level=high
git diff --check -- label-printer-miniapp
```

自动化通过只证明 Node 可加载的逻辑、mock 服务、WXML 绑定、静态资源和本地包体门禁。以下证据仍未取得，不能在发布说明中写成已完成：

- 正式 AppID 下微信开发者工具编译、预览、上传与审核；
- Android/iOS 的相机权限、前后台、杀进程、蓝牙开关和 MTU；
- D11/D110/B1/B21 目标族的真实打印、异常中断和样张读回；
- `2320 → d110`、`4098 → b1` 候选映射的对应真机确认；
- 隐私保护指引、类目、数据删除流程、品牌/模板/图片/字体再分发授权；
- 逐模板视觉审校、无障碍与 8–12 人可用性测试。
