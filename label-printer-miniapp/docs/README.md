## 文档维护规则

1. 需求变化先更新带 ID 的需求/功能规格，再更新追踪矩阵、测试计划和发布清单。
2. 协议、schema、存储键或模块导出变化时，同一提交更新对应技术文档和回归测试。
3. 不把旧测试数量、覆盖率或包体快照复制到多份文档；冻结候选以命令原始输出和微信上传报告归档。
4. 没有正式 AppID、微信编译、Android/iOS 真机、目标打印机样张、隐私/类目和内容授权证据时，状态保持“未放行”。
